# Rehearse — Agent Guide

Rehearse is an AI speaking coach for presentations and business meetings. The user gets a topic, records themselves speaking, and gets feedback on fillers, pauses, pitch/tone, pace, grammar, vocabulary, and formality — then re-records and sees the score improve.

## Workspace

Bun workspace. Two apps:

| Path | What | Stack |
| --- | --- | --- |
| `apps/desktop` | The product. Records and analyses speech locally (Whisper, Praat). | Tauri 2 (Rust) + React + TypeScript + Vite, TanStack Router + Query, oRPC client |
| `apps/web` | Web presence + backend API + background jobs (Inngest) that call the feedback LLM (Groq). Never sees audio. | TanStack Start (React), oRPC, Drizzle + Postgres, Tailwind v4 (landing page) |

Commands (from repo root):

```
bun install
bun run dev             # mprocs: web + desktop + inngest (+ db-studio on demand), see mprocs.yaml
bun run dev:desktop     # tauri dev (fetches the Praat sidecar first)
bun run dev:web         # http://localhost:3000
bun run dev:inngest     # Inngest dev server, http://localhost:8288 (runs feedback jobs locally)
bun run build:desktop
bun run build:web
bun run lint            # ultracite: oxlint (type-aware) + oxfmt format check
bun run format          # ultracite: auto-fix lint + format

```

**Deploying:** see `docs/DEPLOYMENT.md`. Web: Netlify from `apps/web/netlify.toml` (site base directory `apps/web`; `@netlify/vite-plugin-tanstack-start`, loaded only for `vite build` because its dev emulation crashes `vite dev`; production runs migrations first; 60 s function limit, so LLM calls time out at 50 s). Desktop: push a `v*` tag matching `apps/desktop/package.json` (the version's single source; `tauri.conf.json` reads `../package.json`; in beta it's `0.1.0-beta.N`, shown to customers as a `Badge` next to the logo in the app and on the website, so Windows ships NSIS only since an MSI version must be numeric, and releases stay non-prerelease because `releases/latest` skips prereleases) → `.github/workflows/release-desktop.yml` builds all platforms with `tauri-action` into a draft GitHub Release with signed updater artifacts, then its `updater-json` job writes `latest.json` once from the `.sig` files (builds set `uploadUpdaterJson: false`: parallel jobs editing one shared file could drop a platform) (`src-tauri/tauri.release.conf.json` turns them on only there, so local builds need no key). macOS builds need `bundle.macOS.minimumSystemVersion` `11.0` (whisper.cpp uses `std::filesystem`, unavailable below 10.15; Tauri's 10.13 default broke release builds) and `src-tauri/build.rs` links clang's runtime (`clang_rt.osx`) for whisper.cpp Metal's `@available` checks. x86 release builds set `GGML_NATIVE=OFF` with `GGML_AVX`/`AVX2`/`FMA`/`F16C` (the release workflow's env; whisper-rs-sys passes `GGML_*` to CMake), so whisper.cpp isn't tuned to the CI runner's CPU (AVX-512) and crash users' machines; Apple Silicon stays native. The bundle is signed: release builds use a self-signed certificate from the `MACOS_SIGNING_CERTIFICATE` / `MACOS_SIGNING_CERTIFICATE_PASSWORD` secrets, which a workflow step imports into a temporary keychain and passes to Tauri as `APPLE_SIGNING_IDENTITY` (its SHA-1; Tauri's own `APPLE_CERTIFICATE` import only resolves Apple-issued names). A stable identity keeps macOS permissions (microphone, the Keychain sign-in) across updates; ad-hoc signing names the app by a per-build hash, so every update reset them. Without the secrets, or locally, it falls back to ad-hoc (`bundle.macOS.signingIdentity: "-"`); unsigned, the bundle has no sealed resources and macOS calls a downloaded copy "damaged". Both only show in release builds: `tauri dev` ignores the minimum. `tauri-plugin-updater` checks `releases/latest/download/latest.json` once per launch in release builds (`modules/common/components/update-checker.tsx`) and downloads a newer release in the background without installing it (installing closes the app on Windows); while it downloads, `UpdateDownloadIndicator` (same file as `UpdateCard`) shows a small muted `Spinner` at the right end of the sidebar's logo row, labelled (and titled on hover) with the version and whole-percent progress; a toast announces it once and `UpdateCard` (`modules/common/components/update-card.tsx`, in the sidebar above the usage meter, not dismissable) offers Restart until the student restarts, which installs and relaunches (`modules/common/lib/update.ts`). `.github/workflows/ci.yml` runs lint, typecheck, tests, rustfmt and clippy on PRs. Keep API changes backwards compatible: installed apps lag behind.

**Releasing the desktop app** (full guide: `docs/DEPLOYMENT.md` → Releasing). The release workflow's first job checks that the pushed tag equals `v` + `version` in `apps/desktop/package.json`, and fails with `Tag vX doesn't match package.json version Y` otherwise. So the version is bumped and merged **before** tagging, never the other way round:

1. On a branch `release/vX.Y.Z-beta.N`, bump `version` in `apps/desktop/package.json` (the only place; `tauri.conf.json` reads it). Betas count up: `0.1.0-beta.2` → `0.1.0-beta.3`. Commit `release: vX.Y.Z-beta.N`, open a PR, merge it.
2. Tag the merged commit on `main` and push only that tag:
   ```sh
   git checkout main && git pull
   grep '"version"' apps/desktop/package.json   # must print the version you're about to tag
   git tag v0.1.0-beta.3
   git push origin v0.1.0-beta.3
   ```
3. GitHub Actions → **Release desktop**: check → four builds (macOS arm64 + x64, Linux, Windows) → Write latest.json. Takes a while (whisper.cpp compiles on every platform).
4. Download an installer from the **draft** release and try it. Drafts are invisible to `releases/latest`, so neither installed apps nor the website's download links see it yet.
5. Edit the release, write notes, **Publish**. Installed apps pick it up on their next launch; website downloads switch within 5 minutes (CDN cache).

A tag pushed too early (the check failed, or a build failed and needs a code fix): delete it on GitHub and locally, fix or bump on `main` through a PR, then tag again. If the failed run left a draft release, delete that too.

```sh
git push origin :refs/tags/v0.1.0-beta.3   # delete the remote tag
git tag -d v0.1.0-beta.3                   # delete the local tag
```

Never re-use a version that was already **published**: installed apps only move to a newer version. Ship the fix as the next beta instead.

Web changes (`apps/web`, including the API and Inngest functions) need none of this: Netlify deploys every merge to `main`. Only desktop changes need a release, and API changes must stay backwards compatible because installed apps update late.

Linting/formatting is **Ultracite on Oxlint + Oxfmt** (no Biome, ESLint, or Prettier). Config: root `oxlint.config.mts` (presets `core`, `react`, `shadcn` + `@shadcn/lint` plugin) and `oxfmt.config.mts`; `apps/web/oxlint.config.ts` extends root and adds the `tanstack` preset. `@shadcn/lint` flags class names Tailwind doesn't know. Types: `type` aliases, not `interface` (lint-enforced everywhere; the only exception is a `declare module` augmentation, which needs `interface` and gets a `// oxlint-disable-next-line typescript/consistent-type-definitions` on that line), derive with `Pick`/`Omit`/`Extract`/`z.infer`/`$inferSelect` instead of redeclaring shapes. Style: `function` declarations for named functions (convention, `func-style` is off) and components (enforced), arrows only inline (e.g. callbacks); the rules enforce kebab-case filenames, sorted object keys, no `||` for defaults (use `??`), no unsafe `as` casts. Run `bun run format && bun run lint && bun run typecheck` before finishing any task.

**TypeScript 7** (native compiler) in both apps. Import from `src/` with the `@/` alias only (`@/styles.css?url`, `@/app`), never `./` or `../`. Alias is defined once in each app's `tsconfig.json` `paths`; Vite reads it via `resolve.tsconfigPaths`.

## Web backend

The API is **oRPC v2** (`2.0.0-beta.43`, pinned) inside TanStack Start. All server code lives in `apps/web/src/server/`; each feature is one folder in `src/server/modules/`.

```
src/
├── env.ts                         # global t3 env (server vars + VITE_ client vars); use `env`, never process.env
├── lib/orpc.ts                    # typed client: in-process on the server (SSR), RPCLink + batching in the browser
├── routes/api/
│   ├── rpc.$.ts                   # wiring: rpcHandler (typed client transport) at /api/rpc
│   ├── inngest.ts                 # wiring: Inngest serve endpoint at /api/inngest
│   └── $.ts                       # wiring: openapiHandler (REST, /api/spec.json, /api/docs) at /api
└── server/
    ├── orpc.ts                    # Context type, publicOS (400/500 declared, declaredErrorsOnly), protectedOS (+401/403, session)
    ├── errors.ts                  # defineError(), ERROR_STATUSES, shared error classes
    ├── constants.ts               # global server constants (COOKIE_OPTIONS: HttpOnly, Lax, Secure in production)
    ├── router.ts                  # root router { auth, feedback, topics }, AppRouter type
    ├── inngest.ts                 # Inngest client (dev server in development, Cloud in production)
    ├── handlers.ts                # RPCHandler + OpenAPIHandler wiring (CORS, batch, response headers, CSRF, coercion, docs)
    ├── core/
    │   ├── declared-errors.ts     # declaredErrorsOnly middleware + declaredErrorsPlugin (undeclared → typed 500, bad decode → 400)
    │   ├── input-validation.ts    # inputValidation middleware (422 + prettified issues)
    │   └── openapi.ts             # OpenAPI generator, error body schemas, generateOpenAPISpec()
    ├── db/                        # client.ts (drizzle + postgres), schema.ts (tables)
    └── modules/<name>/
        ├── <name>.router.ts       # required: procedures
        ├── <name>.schemas.ts      # required: Zod input/output schemas + z.infer types (Zod-only imports)
        ├── <name>.errors.ts       # module error classes (error factory)
        ├── <name>.service.ts      # optional: logic + DB, no oRPC imports
        ├── <name>.middleware.ts   # optional: oRPC middleware (e.g. auth's requireSession)
        └── <name>.constants.ts    # optional: CONST_CASE tunables; no `env` (schemas import it)
```

- **Procedure = one chain:** `publicOS` (or `protectedOS`)`.meta(openapi({ method, path, summary, tags, successStatus? })).use(inputValidation).input(schema).output(schema).errors({...}).handler(({ input, errors }) => ...)`. Register it in the module's router object and the module in `server/router.ts`.
- **Errors are classes** made with `defineError(code, { message, data?, status? })` from `server/errors.ts` and thrown with `throw new X()`:
  - Standard HTTP codes (`BAD_REQUEST`, `NOT_FOUND`, `UNPROCESSABLE_CONTENT`, …) are only for the shared classes in `server/errors.ts`; they take their status from oRPC's `COMMON_ERROR_STATUS_MAP`.
  - **Module errors always use module-prefixed `SCREAMING_SNAKE` codes** (`AUTH_INVALID_CREDENTIALS`) and declare a standard HTTP status next to them: `defineError("AUTH_INVALID_CREDENTIALS", { status: 401, message, data? })`. A custom code without `status`, a lowercase code, a non-HTTP status (e.g. 418), or `status` on a standard code all fail to compile; reusing a custom code with a different status throws at startup.
  - `defineError` registers custom statuses in `ERROR_STATUSES`, which both handlers and the OpenAPI generator use. There is no hand-maintained status map.
  - Shared classes live in `server/errors.ts` (`BadRequest`, `InternalServerError`, `InputValidationFailed`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`); module classes in `<name>.errors.ts`.
  - Declare every class a procedure throws: `.errors({ [AuthInvalidCredentials.code]: AuthInvalidCredentials })`.
  - Importing `error` or `ORPCError` from `@orpc/server` is lint-banned outside `server/errors.ts` and `server/core/`, so every error goes through `defineError`.
- **Guarantee: a matched procedure only ever returns errors it declares.**
  - `publicOS` declares `BadRequest` (400) and `InternalServerError` (500) on every endpoint.
  - The `declaredErrorsOnly` middleware (procedure level, so SSR calls too) and the `declaredErrorsPlugin` handler interceptor (decode + plugins) turn anything undeclared into a logged (`[orpc] <path> failed`), typed `InternalServerError`. An undeclared `throw new X()` therefore surfaces as 500, never as an untyped error.
  - Malformed bodies/queries (failed decoding) become a typed `BadRequest`.
  - `.use(inputValidation)` before `.input(schema)` adds 422 `InputValidationFailed` (code `UNPROCESSABLE_CONTENT`, `z.prettifyError` message + `data.issues`) only to endpoints with input.
  - The OpenAPI doc therefore lists no `UndefinedError`. Unknown routes return `{ defined: false, code: "NOT_FOUND" }` (no procedure to declare against). Network/proxy failures (499, 502–504) are not part of the API; clients keep one generic fallback for them.
  - `protectedOS` adds `Unauthorized` (401, no/expired session) and `Forbidden` (403, `GetMethodCsrfProtectionHandlerPlugin`). The CSRF plugin is listed before `declaredErrorsPlugin` in `handlers.ts` so the boundary wraps it and the 403 stays typed.
- **Client:** `import { api } from "@/lib/orpc"`; handle errors with `safe(...)` + `isDefinedError(error) && error.code === "AUTH_INVALID_CREDENTIALS"` for typed `error.data`.
- **Frontend-importable server files:** only `src/server/**/*.schemas.ts` and `*.errors.ts` (excluded from Start `importProtection`); everything else in `src/server` is blocked from client bundles.
- **CORS:** `CORS_ORIGINS` (comma-separated), credentials on.
- **CSRF:** session cookie is `SameSite=Lax`; `GetMethodCsrfProtectionHandlerPlugin` blocks cross-site GET navigations. Any public GET it can block would surface as 500, so GET procedures that need it go under `protectedOS`.
- **Context:** `headers`, `clientIp` (from Start's `getRequestIP`, passed in by the routes and the SSR client), `resHeaders` (from `ResponseHeadersHandlerPlugin`; absent for in-process SSR calls, so cookies can't be set there). Cookies via `@orpc/server/helpers` (`getCookie`/`setCookie`/`deleteCookie`).
- **Auth:** student ID + password, **no signups**. Add students: `bun run student:add` from the repo root (`bun run --cwd apps/web`, so the prompts get a real TTY — `bun --filter` wraps output and breaks interactive prompts). `@clack/prompts` asks for student ID, name, password and daily review minutes (default 30) one at a time; re-running with the same ID renames, resets the password or changes the limit. Argon2id via `@node-rs/argon2`; unknown IDs verify against a dummy hash so timing doesn't leak them. Procedures: `auth.login` (POST `/auth/login`; sets the cookie and also returns `token`), `auth.session` (GET `/auth/session`, protected), `auth.logout` (POST `/auth/logout`, 204), `auth.updateProfile` (PATCH `/auth/profile`, protected: renames the student, 1–100 characters trimmed; the student ID never changes) and `auth.changePassword` (POST `/auth/password`, 204, protected: `changePasswordInputSchema` requires at least 8 characters and a new password different from the current one; a wrong current password is `AUTH_INCORRECT_PASSWORD` 400; on success every other session of the student is revoked in the same transaction). The session token is read by `getSessionToken` (`auth.middleware.ts`): an `Authorization: Bearer` header first (the desktop app, cross-site to the API in production, so no cookie), else the cookie (browsers). OpenAPI documents both (`cookieAuth`, `bearerAuth`).
- **Topics:** one `topics` table, plain titles; `student_id` null = shared with every student, set = typed by that student (partial unique indexes on `lower(title)` per scope). `topics.list` (GET `/topics`, protected: own first, then shared) and `topics.create` (POST `/topics`, 201: trims, returns the existing visible topic for a case-insensitive match instead of duplicating). Seed shared topics with `bun run topics:seed` (idempotent; edit the list in `apps/web/scripts/seed-topics.ts`).
- **Feedback** (`modules/feedback/`, PLAN §3.5–3.6): the desktop transcribes and measures locally, then `feedback.submit` (POST `/feedback`, 202) stores the text and numbers in `feedback_jobs` and sends the `feedback/requested` Inngest event; the event carries only the job id. Idempotent per desktop attempt id: a queued, running or finished job is returned; a failed or cancelled one starts over. Each student may send `students.daily_limit_seconds` of speech for review per rolling 24 h (default 30 min, `FEEDBACK_DEFAULT_DAILY_SECONDS`; set per student with `student:add`). Usage is the sum of `spoken_seconds` (rounded up) in the append-only `feedback_requests` table (deleting a review doesn't reset it), checked under a per-student advisory lock so concurrent submits can't overshoot; a talk is accepted while any time is left and counts in full, then `FEEDBACK_RATE_LIMITED` 429. `feedback.usage` (GET `/feedback/usage`) returns `usedSeconds`, `limitSeconds` and `refreshesAt` (when enough time leaves the window, only while the limit is used up); Inngest unreachable → `FEEDBACK_UNAVAILABLE` 503. The `review-attempt` Inngest function (`feedback.functions.ts`) runs durable steps: claim → key points (cached in `key_points` per topic and target length) → Call A (language) alongside the better version's rewrite steps (`rewrite-1`…`rewrite-n`, in parallel) → Call B (content) → complete. Each stage is written to the row (`feedback.get`, GET `/feedback/{id}`) and published with `step.realtime.publish` on the channel `feedback:<jobId>`; the desktop gets a browser-safe token from `feedback.subscribe` (POST `/feedback/{id}/subscription`). **Re-run (feature flag):** students whose student ID is in `FEEDBACK_RERUN_STUDENT_IDS` (`feedback.schemas.ts`, `canRerunFeedback`; now `01`) may send `rerun: true` with `feedback.submit` to review a finished attempt again (no new daily-limit usage); anyone else gets 403. The desktop shows "Re-run analysis" in the rehearsal page's toolbar for them on a ready or failed attempt: `rerunAnalysis` (`runner.ts`) deletes the `.speech.json` cache, clears the attempt's result (`queueRerun`) and runs the whole pipeline again on the same recording (WAV, Whisper, Praat, metrics, review); the `rerun` mark is kept in memory until the submit succeeds. Key points stay cached per topic. `feedback.remove` (DELETE `/feedback/{id}`, 204) cancels a running run (`cancelOn` the `feedback/cancelled` event) and deletes the job. A run that hasn't started 5 min after its event is cancelled (`timeouts.start`, `FEEDBACK_START_TIMEOUT`); a job still `queued` 6 min after its last send (`FEEDBACK_STUCK_AFTER_MS`) has no run left (its event was lost, e.g. sent before the app was synced with Inngest), so `feedback.get`, which the desktop polls, sends it a new event. The function retries 4 times; each step uses `openai/gpt-oss-120b` and switches to `openai/gpt-oss-20b` from the third attempt. `onFailure` marks the job failed and publishes it. LLM calls (`feedback.ai.ts`) use the **Vercel AI SDK 7**: `generateText` + `Output.object` (Zod), strict JSON schema on Groq, reasoning effort low, temperature 0.2, `maxRetries: 0` (Inngest owns retries), 120 s timeout. Groq 429 becomes `RetryAfterError` (Groq's retry-after), 401/403/404/413 become `NonRetriableError`. The output schemas are strict-mode friendly: every field required, no min/max. `feedback.sanitize.ts` then drops findings whose quote isn't really in the cited sentence, grammar and vocabulary quotes containing a hesitation (`uh`, `um`), repetition findings for the topic's own words, key terms and fillers, trims lists to the duration-scaled limits (`limitsFor`), clamps rubrics to 1–5 and aligns coverage with the key points. Prompts live in `feedback.prompts.ts`. Every call is told who the students are (`STUDENTS`: Pakistani university students, Urdu/Punjabi first language, Pakistani English): local words and names are fine, typical L1-transfer mistakes are looked for, likely speech-recognition errors (a name spelled two ways) are skipped, and explanations stay in simple English. rubrics are judged against a clear professional talk, not effort (a halting, error-filled talk gets 1–2); The better version's `rephrasings` come from their own small calls, not Call A: `rewriteChunks` splits the talk into groups of at most 12 sentences or 2,000 characters (`REWRITE_CHUNK_SENTENCES`/`_CHARS`), each with the two sentences before it as context, and one `rewrite-n` step per group (`rewriteSentences`, `REWRITE_INSTRUCTIONS`) rewrites every sentence that still wouldn't read well once fillers are out (false starts, cut-off words, broken grammar, literal Urdu phrasing) in simple spoken English, keeping the student's ideas, order and local words. That keeps every answer small and quick whatever the talk's length (one Call A writing the whole talk ran out of output tokens on Groq). The model returns only `{ i, better, why }` (`rewriteOutputSchema`) and `sanitizeRewrites` keeps sentences of its group and fills `quote` with the whole sentence, so the stored result keeps the shape installed apps read. Call A (`languageOutputSchema`, `LANGUAGE_INSTRUCTIONS`) has no rewrites; both share `STUDENT_RULES` and `FIX_RULES`. On Groq's free tier (8,000 tokens per minute, input plus output per request) the parallel steps wait out 429s (retry-after) and long talks can't fit at all; production needs the Developer tier. Call A also returns pause picks (thorough, with spot-specific reasons) and `emphasis` (words to stress) for the better version. Token usage accumulates on the job row. Env: `GROQ_API_KEY` (required), `INNGEST_EVENT_KEY` / `INNGEST_SIGNING_KEY` (production only; the dev server needs neither).
- **Sessions:** random token in an HttpOnly `session` cookie (`SameSite=Lax`, `Secure` in production, 30 days); only its SHA-256 is stored, with student, expiry, IP, user agent. Protected procedures read `context.session` (`{ expiresAt, student }`) and `context.sessionToken` (the raw token, to tell the current session apart from the student's others).
- **Docs** (non-production): `/api/docs` (Scalar), `/api/spec.json` (OpenAPI 3.2), generated from the router.
- **DB:** Drizzle + `postgres`; `db.select()/insert()/update()/delete()` only, never `db.query.*`. Tables in `src/server/db/schema.ts`; migrations in `drizzle/` (committed).

```
bun --filter web db:generate   # create migration from schema changes
bun --filter web db:migrate    # apply migrations
bun --filter web db:studio     # browse data
bun run topics:seed            # add shared topics (idempotent)
```

## Desktop app

TanStack Router (file-based, code-split) + TanStack Query + oRPC client. All routes live in one place, `src/routes/` (TanStack's default; the plugin generates `routeTree.gen.ts` from it). Each feature's code is one folder in `src/modules/`; route files stay thin and import their page from the module.

```
src/
├── main.tsx                       # QueryClientProvider + RouterProvider
├── router.tsx                     # queryClient, router (context: { queryClient }), Register
├── routeTree.gen.ts               # generated, committed
├── routes/                        # every TanStack file route (thin: beforeLoad + component)
│   ├── __root.tsx                 # beforeLoad: context.session (Session | null) from loadSession() + openDatabase()
│   ├── (auth)/                    # route.tsx = requireGuest layout; login.tsx
│   └── (private)/                 # route.tsx = requireSession guard; onboarding.tsx (until the mic is allowed); session.tsx (full-screen setup → speak → save/analyse, ?topic&topicId&minutes&rehearsal)
│       └── (app)/                 # route.tsx = AppLayout (history sidebar + page, loads rehearsals); index.tsx (new rehearsal, preloads topics + progress without waiting); rehearsals/$id.tsx (one rehearsal thread, ?attempt=n); settings.tsx (profile, password, theme)
└── modules/
    ├── common/
    │   ├── lib/env.ts             # t3 env (VITE_API_URL, default http://localhost:3000)
    │   ├── lib/orpc.ts            # `api` (typed RouterClient<AppRouter>, bearer token from the OS credential store) + `orpc` (TanStack Query utils)
    │   ├── lib/query-client.ts    # createQueryClient(): no retry on 401
    │   ├── lib/errors.ts          # isUnauthorized(error), getErrorMessage(error, fallback)
    │   ├── lib/recordings.ts      # audio files in $APPDATA/recordings (format pick, append, read, delete, list)
    │   ├── db/                    # schema.ts (tables), client.ts (Drizzle sqlite-proxy → Rust), migrate.ts, init.ts (openDatabase)
    ├── analysis/                  # background analysis: lib/runner.ts (the job), audio.ts, speech.ts (Rust bridge), metrics.ts, report.ts; components/ (checkpoints, runner mount)
    │   └── components/app-layout.tsx # (private) shell: sidebar-colored frame, HistorySidebar + page panel
    └── <name>/                    # only the folders a module needs
        ├── pages/                 # one component per route, imported by src/routes/
        ├── components/
        ├── queries/               # queryOptions
        ├── actions/               # mutation hooks (useX)
        └── lib/
```

- **Route groups:** `(private)/(app)` = pages inside the sidebar shell; `(private)` pages outside it (the session) are full-screen. `(auth)` = logged-out only (`requireGuest`, context `session: null`, logged-in → `/`); `(private)` = logged-in only (`requireSession`, context `session: Session`, logged-out → `/login`). Both layouts are `src/routes/(auth)/route.tsx` and `src/routes/(private)/route.tsx`; add a page by putting its route file in the matching group folder so it inherits the guard.
- **Launch:** `__root` awaits the session (`loadSession`) and the local database in `beforeLoad`; its `pendingComponent` is `SplashPage` (`modules/common/pages/`, just the centered logo from `src/assets/logo.svg`) with `pendingMs: 150`, so only slow launches show it (then held for the default 500ms minimum). Nothing else blocks launch on the network: pages load their server data behind per-component skeletons (`Skeleton`, `src/components/ui/skeleton.tsx`), e.g. the home page's topic header and progress stats each sit in their own `Suspense`, while the length picker is usable at once. `index.html` inlines the light/dark `--background` so the window isn't white before CSS loads; keep it in sync with `index.css`.
- **Microphone onboarding** (`modules/onboarding/`): `(private)/(app)` and `session` run `requireMicrophone` in `beforeLoad`, which redirects to `/onboarding` until the mic is allowed; `/onboarding` redirects home once it is. `getMicrophoneAccess()` uses the Permissions API but also remembers a successful `getUserMedia` in `localStorage` (`microphone-granted`), because WKWebView reports "prompt" even after the OS granted access; an explicit "denied" clears it. On denial the page links to the OS privacy pane via `@tauri-apps/plugin-opener` (`x-apple.systempreferences:` / `ms-settings:` are allowed in `capabilities/default.json`). macOS needs `NSMicrophoneUsageDescription` in `src-tauri/Info.plist` (merged into the app; without it asking for the mic crashes) and the `com.apple.security.device.audio-input` entitlement (`src-tauri/Entitlements.plist`) for hardened-runtime builds. wry grants the webview-level request, so only the OS prompt appears.

- **Analysis** (`modules/analysis/`, PLAN §3): a background job (`lib/runner.ts`), started for the logged-in student by `AnalysisRunner` in the `(private)` layout. It resumes every `processing` attempt on launch and stops on logout. Local steps run one attempt at a time:
  1. Decode the recording in the webview and resample it to a 16 kHz mono WAV (`audio.ts`, `recordings/<id>.wav`, deleted afterwards).
  2. Download the speech model if missing (Rust, ~1.6 GB, resumable, SHA-256 checked). `lib/model.ts` keeps one download app-wide (`downloadSpeechModel` starts or joins it; `useSpeechModel` reads its state and bytes). The home page's `SpeechModelCard` (`components/speech-model-card.tsx`) shows until the model is there: Download opens a `Dialog` with a `Progress` bar (`src/components/ui/progress.tsx`, React Aria `ProgressBar`; GB via `formatBytes`, then "Checking the download" while Rust verifies it); hiding the dialog keeps it going and the card shows the percent. The runner joins the same download if an attempt needs the model first.
  3. CrisperWhisper via `whisper-rs` (Metal on macOS) for a verbatim transcript with word timings. Fillers depend on three things (`speech.rs`):
     - **Verbatim mode:** the decoder prompt is `[verbatim_1]…[verbatim_5]` (ids 50373–50377), as in `crisperwhisper/prompt.py`. Without it the model writes cleaned "intended" text: no fillers, grammar silently fixed.
     - **`[UM]` (50358):** whisper.cpp suppresses it as a "language token". The `allow_fillers` logits filter restores its raw logit; it only reads rows of the current batch (row 0, or the last verbatim-prompt row on a window's first step), checks reference tokens match exactly, and runs only if `has_filler_tokens` confirms the vocab.
     - **`[UH]` (50359):** whisper.cpp leaves it out of segment text, so words are built from tokens (`words_from_tokens`), mapping both to "um"/"uh".

     - **Word timings:** onsets come from whisper.cpp's DTW alignment with CrisperWhisper 2.0's alignment heads (`ALIGNMENT_HEADS`, from its `generation_config.json`); each word ends where the next starts. The decoder's own token timestamps spread words across a chunk from its start (seconds early), which put pauses on the wrong words. Pauses are Praat's silences, placed before the first word whose onset is at or after the silence start, minus 150 ms (`metrics.ts`): aligned onsets sit at either edge of a silence, never well before it.

     whisper.cpp keeps a prompt only for the first 30 s window (`carry_initial_prompt` is private in whisper-rs), so the audio is cut into chunks of ≤ 28 s at the quietest 100 ms after 18 s (silent chunks skipped). Each chunk is decoded alone: greedy, temperature 0, `single_segment`, timestamps on (no-timestamps mode and logit bonuses both did worse). A filler can't directly follow a filler (at temperature 0 one "uh" otherwise repeats forever). Loops (`LOOP_THRESHOLDS`, from `crisperwhisper/loop_detection.py`) are repaired by keeping the words before the loop and decoding the rest again, verbatim once more, then intended. Check filler detection on a real recording with `REHEARSE_TEST_WAV=talk.wav cargo test --release transcribes_wav -- --ignored --nocapture` (16 kHz mono WAV).

  4. Praat for pitch, loudness and silences (if Praat fails, pauses fall back to word gaps).

  Steps 1–4 are cached in `recordings/<id>.speech.json` (with `SPEECH_VERSION`, now 3; bump it when transcription changes so old caches transcribe again). Then come metrics (`metrics.ts`: sentences, fillers, candidate fillers for the LLM, pauses from Praat silences, WPM, repetition and pause candidates, pitch spread) and `feedback.submit`. While the server reviews, the next attempt's local steps can start. The runner follows the job over Inngest realtime and also polls `feedback.get` every 10 s, so a dropped socket or a restart never loses the result. Submissions retry with backoff (5 s → 60 s) while offline. When the job completes, `report.ts` builds the transcript markup, the subscores and the score (PLAN §4.3). It also builds the better version, a script to read aloud: changed wording carries what was said and why; fillers and stutters are removed; a silent pause marks where a filler was only where a speaker would logically pause (a natural break: sentence start, next to punctuation, before a capitalised word the recognizer didn't split off; or mid-phrase before a word that opens a clause, like "because" or "which"), never right after a little word like "and", "the" or "don't" (`canPauseBefore`, applied to the LLM's pause picks too; a comma after such a word only counts at the sentence start); repeats go even across a filler and as pairs ("in uh in", "for the for the"), as do cut-off words and a joining word left before another ("And, you know, but because" → "But because"); "like" right after "don't", "to", "I" and similar stays a verb even if the review called it a filler (`isVerbLike`, so it isn't counted either); pauses go where the LLM picked them (with reasons) and wherever the student ran straight into the next sentence; side-by-side pauses collapse to one; words to stress come from the LLM `emphasis` list, and `completeAnalysis` stores them; a toast offers to open the thread. Failures mark the attempt `failed` with a student-facing `error`; `retryAnalysis` requeues it (also "Analyse it" for interrupted talks of 30 s or more). `cancelAnalysis` aborts it and stops whisper (used when deleting). Progress is in memory (`useAnalysis(id)`, `useSyncExternalStore`) and rendered as checkpoints by `AnalysisSteps` (session analyse phase, attempt guide). Rust side: `src-tauri/src/speech.rs` (`speech_model_status`, `speech_download_model`, `speech_transcribe`, `speech_cancel`, `speech_prosody`; refuses to load the model with under 3 GB free RAM). whisper-rs 0.16's `set_abort_callback_safe` must be given an already boxed `dyn FnMut`, otherwise its trampoline reads garbage and aborts encoding. Praat (GPL, separate process only) is a Tauri `externalBin` sidecar fetched by `apps/desktop/scripts/fetch-praat.ts` (pinned 7.0.02, SHA-256 checked; on macOS thinned with `lipo` and signed ad hoc, since the binary outside its `.app` is killed); the prosody script is `src-tauri/src/prosody.praat`.

- **API URL:** `VITE_API_URL`. The web API must list the desktop origin in `CORS_ORIGINS` (dev: `http://localhost:1420`).

## Core loop

1. Pick a topic (generated by the LLM, categories: presentation / meeting / pitch / interview).
2. 30s prep, then record 60–120s.
3. Analyze (pipeline below).
4. Show overall score % + subscores first.
5. Reveal mistakes progressively: top 3 expanded, the rest collapsed by category (Fillers, Pauses, Pace, Pitch/Tone, Grammar, Vocabulary, Structure). Each mistake = what was said → better version → why.
6. Retry the same topic focused on the top 3. Show diff vs previous attempt ("Fillers 14 → 5, score 62% → 78%").
7. Track progress across sessions.

## Analysis pipeline

Speech is analysed on the device; only text and numbers go to the backend, which reviews them with the LLM in a background job.

| Step | Where | Tool | Output |
| --- | --- | --- | --- |
| 1. Verbatim transcript | Desktop (Rust) | **CrisperWhisper 2.0 large** (GGML q8) via whisper.cpp (`whisper-rs`) | Words incl. fillers/false starts + word timings |
| 2. Prosody | Desktop (sidecar) | **Praat** (`praat --run prosody.praat`) | Pitch contour, loudness, silences |
| 3. Metrics | Desktop (TypeScript) | Our code, no AI | Fillers, WPM, pauses, repetition and pause candidates, pitch spread |
| 4. Feedback | Backend (Inngest job) | **gpt-oss-120b on Groq** via the AI SDK (fallback gpt-oss-20b) | Key points, grammar, vocabulary, rephrasings, repetition, pauses, coverage, content check |
| 5. Score + report | Desktop (TypeScript) | Our code | Transcript markup, better version, subscores, score |

## Hard rules

- **No Python in the shipped app.** Everything is Rust + C++ engines + sidecars. PyTorch is too big to ship.
- **Models are downloaded on first launch, never bundled** in the installer.
- **RAM budget:** only the speech model runs locally (~2–2.5 GB). Check free RAM (`sysinfo`) before loading it and refuse with a clear message rather than swap (3 GB minimum free).
- **Numbers come from code, not the LLM.** Counts, timings, WPM, pitch stats, and the score are computed deterministically. The LLM only explains and suggests.
- **LLM output is schema-constrained JSON** (Groq strict JSON schema via AI SDK `Output.object`). Reasoning effort low. Temperature 0.2. The Groq key lives only on the server.
- **LLM must quote the exact phrase** for every mistake, and must not flag normal spoken fragments as errors.
- Focused LLM calls per attempt, never one giant prompt: A (language, repetition, pauses, coverage), B (content check), the better version's rewrites in small groups of sentences, plus cached key points.
- Audio never leaves the user's machine.
- Targets: macOS, Windows, Linux. Don't use platform-specific APIs without a fallback for the other two.

## Scoring

Computed in `modules/analysis/lib/report.ts` (PLAN §4.3); the LLM only supplies 1–5 rubrics and the lists that are counted.

```
score = 0.25*fluency     (fillers/min, hesitations/min, longest pause)
      + 0.10*variety     (flagged repetitions per minute)
      + 0.10*pace        (WPM vs 130–160, time spoken vs target)
      + 0.05*delivery    (pitch spread in semitones)
      + 0.20*grammar     (LLM rubric, minus errors per 100 words)
      + 0.15*vocabulary  (LLM rubric)
      + 0.15*flow        (key-point coverage + coherence rubric)
```
